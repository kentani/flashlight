# 3〜6歳の子どものためのUI/UX

対象ユーザーは、自分で読める文字がまだ限られ、指先での細かな操作や長い手順が難しい3〜6歳の子ども。保護者の説明がなくても「やってみたい」「できた」が続く体験を目指す。

## 設計時の判断軸

- 画面ごとに主役の遊びと最初にすることを一目で分かるようにする。選択肢・説明・設定は、その行動を邪魔しない。
- 操作はタップ、ドラッグなど直感的なものを優先し、短い流れで遊び始められるようにする。小さなボタン、長押し、正確な操作、読解を成功条件にしない。
- 文字は短く、やさしい日本語を使う。意味を補う絵・形・色を添えるが、色だけで状態や操作を伝えない。
- タップできる範囲は見た目より十分に広く取り、触れたときに反応することを明確にする。誤操作しても、すぐやり直せ、罰や行き止まりにならない。
- 子どもの入力にはすぐに楽しい反応を返す。遊びに合う短い音、動き、色や形の変化を組み合わせる。音はユーザーの操作後に鳴らし、音量を急に大きくしない。音が出せない・消している場合にも、同じ結果が視覚的に分かるようにする。
- 遊びのテーマに合う背景・案内・反応を揃え、画面全体でごっこ遊びの世界観をつくる。ただし、動きや装飾で主役の操作を見失わせない。

## 実装前後の確認

実装前に、近い既存のおもちゃ画面と共通コントロールを確認し、このガイドと両立する形で見た目・操作をそろえる。実装後は少なくともモバイル幅とデスクトップ幅で、次を確認する。

- 初めて開いた子どもが、説明を読まなくても最初の操作を見つけられるか。
- タップまたはドラッグごとに、何が起きたかすぐ分かる反応があるか。
- 小さな画面でも主役の遊びと主要操作が隠れず、片手でも無理なく届くか。
- 音の再生失敗・ミュート時でも、遊びを続けられるか。
- 戻る・リセット・終了のような操作を誤って選んでも、遊びや成果を不必要に失わせないか。

具体的な画面要件がこのガイドと異なる場合は、ユーザーの依頼を優先し、その差分を明示する。
